## Broader repeated-reason audit needed before freeze

The ledger also excludes 65 package candidates with “covered as a concrete mount/configuration option” and 64 with “documented through its stable seam” across Host and Client topics. The table above lists high-confidence Infra/Cordis examples. A candidate that actually appears as a selected mount/configuration option belongs in `merged` with a **real included primary candidate**, owner and distinct activation conditions. A package never used in a selected task may remain `excluded`, but its reason should identify its actual role and why the external plugin task does not need it. Similarly, `api-surface.json` currently excludes many *required parameter/result types* as “not used directly”; declarative fields and structural TypeScript types are part of the callable contract and must be reconciled with the reference text, not filtered by whether a task invokes them as functions.

## Checks performed and limits

Read the current ledgers, target package declarations, implementation entry points, cookbook, tutorial and package READMEs. I did not run provider tests, install optional external programs or independently prove default activation. This audit proposes ledger edits; it does not certify the broad 65/64 groups or the experimental integrations as end-to-end verified.
