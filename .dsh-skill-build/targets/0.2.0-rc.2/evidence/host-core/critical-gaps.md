# Host/Core critical included-object gaps

Target: `dsh-v0.2.0-rc.2` at `639ed015397290b3745d163aafe02ffee4aa3f84`. This records a focused comparison of the **251 originally `included` API-object proposals** in `host-core/reconciliation.json` with `skill-source/api-guardrails/host-core*.md` and `skill-source/how-to/host-core.md` before remediation. A symbol missing from prose was not automatically a gap: these 19 rows were selected for direct task use, correctness of a documented branch, or a proposed inclusion that should be reversed. The 17 `included` gaps are now addressed in their indicated Host source sections; the two `excluded` corrections are reflected in the narrowed reconciliation proposal. Source paths below are relative to the exact checkout.

The two `excluded` rows are corrections to this agent's own earlier recommendations. A further correction to the earlier reconciliation proposal is that `LlmModelDiscoveryOperation` belongs to the pi-ai discovery helper (`packages/llm/llm-pi-ai/src/discovery.ts:270`), while `LlmRuntime.registerModelDiscovery` takes `LlmModelDiscoveryRequest` and a separate signal; the former should not be included solely for this Host callback. The other rows identify missing semantics in the selected task's existing owner, not a request to duplicate the full exported symbol inventory in prose. Runtime coverage is unchanged: the existing HOW-TO marks end-to-end adapter, Session restore, workflow, and hook paths as unexecuted where applicable.
