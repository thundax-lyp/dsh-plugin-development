# Client Settings Form 与卡片入口

## 适用范围与入口

目标 `dsh-v0.2.0-rc.1` 的浏览器插件从 `@deepseek-ai/dsh-client-ui-settings/client` 取得 `ctx.configForms` 及 `ConfigForm<T>` 类型；从 `@deepseek-ai/dsh-client-ui-primitives` 取得 `SettingsFormModel`、`settingsTextField`、`settingsNumberField`、`SettingsForm`、`SettingsValueField` 和 `SettingsSecretField`。前者负责共享 Host describe 镜像和按 namespace 排队的写入，后者负责 staged 草稿与 React 控件。Host namespace、volatile Config、revision 和秘密遮蔽的权威契约在 [Host 设置](api-settings.md)；本页只拥有 Client 表单契约。把卡片放入 Plugins 页的 slot 路径见 [添加插件设置卡片](how-to-add-plugin-settings-card.md)。

正式 Web Profile 有 `ui-settings` 基础行与 `ui-plugin-manager` 页面。客户端模块系统只会为具有 `dsh.client` 元数据、裸包名 Loader 行与构建好的 `./client` 的插件挂载浏览器半边。`@deepseek-ai/dsh-client-ui-settings` 的 Client 插件依赖 `remote` 和 `remote.settings`；它按 Host 是否 loopback 选择 `host` 或 `memory` 模式，后者不开放 Host 持久写入。

## 契约与运行语义

`ctx.configForms.get<T>(entryId)` 以**活动 Profile 的入口 id**取得共享 `ConfigForm<T>`；`entryId` 不是包名、设置标题或凭证 key。返回的 `getSnapshot()` 是同步、引用稳定直至下一次更改；`subscribe` 返回同步 disposer。`set(field,value)`、`unset(field)` 和 `mutate(ops,expectedRevision?)` 都是异步写入，返回 `true` 表示 Host 接受，`false` 表示拒绝或跳过；网络错误 reject。`mutate` 的 ops 以一个 revision fence 原子提交。设置值与 base/user 分层都来自 Host 的同一 describe 镜像；该镜像在 `settings/document-updated` 和 `connection/reset` 后重读，且只让较新的答案获胜。`whileServed(namespaces, register)` 仅在目标 namespace 由 Host 提供时注册页面；返回 disposer 必须交给调用者的 `ctx.effect`。`describe()` 给跨 namespace 目录与 schema 观察用，单 namespace 页面优先用 `get()`。

`SettingsFormModel<T>(scope, specs, secrets?)` 接收一个符合 `SettingsFormScope<T>` 的 form，并订阅其 snapshot。`settingsTextField(field)` 把空白转为 unset、非空文本 trim 后 set；`settingsNumberField(field)` 把空白转为 unset、有限数字转为 set，非法文本使 Save 禁用。模型的 `field(field)` 返回草稿 text、预览 override 状态与 invalid；`shell()` 返回 available/writable/dirty/invalid/saving/failed；`actions()` 提供 edit/resetField/save/discard。`bind(project)` 把模型投影为可订阅 store，slot renderer 可将其绑定成 hook。`save()` 收集本次 staged edits，以草稿初始 revision 调用一次 `scope.mutate`，成功后再执行 write-only secret 写入；失败保留草稿。`dispose()` 只释放表单订阅，组件 `SettingsForm` 卸载时调用 `onDiscard` 丢草稿。`SettingsSecretSpec.write` 是单独的 Host 凭证写入，不与配置文档事务原子提交；秘密不得进入配置 snapshot 或普通字段。

`SettingsForm` 接收 `labels`、`state`、`onSave`、`onDiscard` 和 `children`；`SettingsValueField` 接收字段 state、标签/提示、disabled、edit/reset 回调，可选 `numeric` 仅控制键盘提示，不验证数值。`SettingsSecretField` 接收空白初始草稿、configured 布尔与写入状态标签；blank 保存不改现有凭证。更具体的页面文案、业务 schema、值转换、失败展示和权限由卡片 owner 提供。React 页面不应在每次 onChange 直接向 Host 写入。

## 生命周期与状态

表单 provider 在 Client 插件卸载时等待已跨线的写入并释放所有共享 form。卡片自己释放 `SettingsFormModel.dispose()` 与 `whileServed` disposer；页面卸载清除未保存草稿。Host 持久事实只在 Profile patch/user 层；reconnect 后由共享 describe 镜像重建，不能以本地 staged 草稿代替。`ConfigForm` 的序列化队列只保证**同一 namespace 的该 form**按顺序写入；其他编辑器的并发由 revision fence 和失败后的 Host 重读裁决。

## 失败、权限与边界

Host 未提供 namespace 或非 loopback memory 模式时表单不可用、写入返回 false。只读文档 `writable=false`；卡片应禁用字段，模型拒绝保存。`SettingsForm` 自带只读说明，但其 Save 的 disabled 条件只看 dirty/invalid/saving，因此卡片还需在真实页面检查从可写切到只读时的残留草稿交互。非法字段 text 阻止保存。Host 拒绝最新写入后 form 重新加载；网络错误 reject，`SettingsFormModel.save()` 将它映射为 failed 并保留草稿。若配置与秘密同时提交，配置可能成功而秘密失败；UI 需明确显示并允许重试，不能宣称跨域原子性。`SettingsForm` 的 CSS/React 可见性需要真实浏览器验证，单独模型测试不能证明页面正确。
