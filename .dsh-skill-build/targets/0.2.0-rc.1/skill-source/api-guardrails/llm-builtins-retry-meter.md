# 内置 LLM 路由、重试与 Token Meter

## 包的任务边界

目标 `dsh-v0.2.0-rc.1` 的 `@deepseek-ai/dsh-llm-deepseek` 是官方 Messages adapter 的构件库，根导出 `DeepSeekAdapter`、配置/模型/文件工具及 `registerDeepSeekProvider`，自身不是可直接装载的 Cordis plugin。`@deepseek-ai/dsh-llm-deepseek-api-key` 是已发布可装载 function plugin，固定注册 `deepseek-official`；它的 `Config.apiKeyEnv` 是凭证**引用名**，默认 `DEEPSEEK_API_KEY`，请求时经 Credentials Service 解析；服务未装载时只从受信任启动环境读取同名变量，缺失为 `MISSING_CREDENTIAL`。完整配置任务见 [配置官方 DeepSeek API-key 与重试](how-to-configure-deepseek-api-key-retry.md)。`@deepseek-ai/dsh-llm-deepseek-account` 固定注册 `deepseek-account`，账号 token 的专有路径归 [DeepSeek Account 服务](api-deepseek-account-auth.md)。

`@deepseek-ai/dsh-llm-pi-ai` 可装载为多 route adapter，配置 `providers` 字典；已知 catalog route 可继承模型/协议，未知 route 必须完整声明 `api`、`baseURL` 与模型。`apiKeyEnv` 是每请求凭证引用；该 route 已在 [LLM Provider 适配器](api-llm-providers.md) 归属，不应和固定的 `deepseek-official` route 使用同一 Provider ID。`@deepseek-ai/dsh-plugin-package-inventory-deepseek` 是官方 DeepSeek request 字段的现成贡献插件，其 `Config.enabled` 开关控制 `dsh_plugin_packages`；实际字段注册 seam 由 [DeepSeek 请求扩展](api-deepseek-request-extensions.md) 负责。两个内置包的完整装载例子见[配置 pi-ai gateway 与包清单](how-to-configure-pi-ai-and-inventory.md)。包清单插件不为其他 LLM adapter 添加通用 inventory。

`@deepseek-ai/dsh-llm-retry` 是无 route 配置的 Host function plugin，`inject=['agents','sessionProjections']`；Provider 在其 adapter 的 `providerRetryPolicy` 或现成 route 的 `retryPolicy` 中声明策略。`Config` 必须是空对象；把 `retryPolicy` 塞在 retry plugin 自身会失败。普通模式仅重试列出的 `LlmFailure.code` 且最多 `maxRetries` 次（默认 5，默认暂态码包括空响应、RATE_LIMIT、SERVER、TIMEOUT、TRANSPORT）；always 模式无界重试所有请求错误，直到成功、取消或插件卸载，需慎重。每次等待前先记 `llm/retry` Session 事件，等待后记 `llm/retry-started`，保证恢复可重建；等待响应 Agent 与插件取消，卸载会停止 listener 并 drain 活跃恢复。`providerRetryAfterMs` 在配置上限内优先使用；超上限时普通模式委托后续恢复，always 模式改用本地 backoff。重试仅在 Agent request-error seam 生效，直接调用 `ctx.llm.stream` 不自动重试。

`@deepseek-ai/dsh-token-meter` 是 `ctx.tokenMeter` Service，依赖 `sessionProjections`，配置为空。`measure(session,requestHeader?)` 从 Session 持久日志重放 surface/usage，返回深冻结的 `TokenMeasurement`：`logRevision`、baseline、signed delta、非负 `totalTokens`、`surfaceTokens` 和各节点价格；`estimateMessage(message)` 是固定启发式估算。它不新增模型 Provider，也不是计费结算值；路由声明图像价格时会重新估算当前 surface。读取步骤见 [在插件中读取 Session Token 压力](how-to-read-session-token-pressure.md)。消费方不能把内存中的估算当作必须写入 Session 的新事实，若决策/结果需可重建，应由自己的领域事件记录。

## 对象类型与成员

| 公开对象                                                         | 可用成员与范围                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dsh-llm-deepseek-api-key.Config`                                | 协议设置外增加 `apiKeyEnv` 凭证引用；route 固定为 `deepseek-official`。                                                                                                                                                                                                                                                                        |
| `dsh-llm-deepseek-account.Config`                                | 复用协议设置，无 `apiKeyEnv`；route 固定为 `deepseek-account`。                                                                                                                                                                                                                                                                                |
| `dsh-llm-deepseek.Config` / `Options` / `deepSeekConfigFields`   | Messages 协议设置的 Volatile schema、原始 options 与字段集合，含 baseURL、thinking/reasoningEffort、输出与 context cap、models、stream idle、图像/文件上限、上传 expiry/refresh/quota、retryPolicy。`plainOptions(config)` 取当前值，`resolveAdapterOptions(options, environment?)` 校验并生成请求级快照；不得把原始 Volatile 当成已解析连接。 |
| `DeepSeekConnectionOptions` / `ResolvedDeepSeekOptions`          | 解析后的一次操作快照，含 baseURL、`defaults`、maxTokens、defaultContextWindow、models、streamIdleTimeoutMs、图像/文件限制、`filePolicy` 与已解析 retryPolicy；`RequestDefaults` 是 thinking/reasoningEffort。                                                                                                                                  |
| `DeepSeekCatalogModel` / `catalogModelInfo`                      | 模型目录条目的 id/name/description/contextWindow/maxTokens/inputModalities、图像预算、systemPromptUpdate/toolUpdate；helper 将目录条目映射到通用 LLM model info。目录只供发现，核心调用仍可传其他 model id。                                                                                                                                   |
| `PUBLIC_BASE_URL`                                                | 公开 API 的默认 endpoint 常量；自有 route 要明确自己的受信任 endpoint 与认证来源。                                                                                                                                                                                                                                                             |
| `dsh-llm-pi-ai.Config`                                           | `providers` 字典按 key 注册 route；模型目录和凭证从每个 profile 解析。                                                                                                                                                                                                                                                                         |
| `dsh-llm-pi-ai.name/inject/apply`                                | 可装载 Host plugin，`inject=['llm']`；`apply(ctx, config)` 读取 `Config.providers`，注册目录和可运行 route，fiber 卸载时释放。自声明 route 的配置与无网络 smoke 见[pi-ai 与清单 HOW-TO](how-to-configure-pi-ai-and-inventory.md)。                                                                                                             |
| `dsh-plugin-package-inventory-deepseek.Config/name/inject/apply` | `Config.enabled?: boolean` 默认 true；`name='plugin-package-inventory-deepseek'`、`inject=['agents','deepseekLlmApiExtensions','loader']`；enabled 时注册 `dsh_plugin_packages` 请求扩展，disabled 时无贡献，卸载时释放。只收集活动 Loader 包与可用的 Agent standing preset。                                                                  |
| `dsh-llm-retry.Config`                                           | 空对象；`retryPolicy` 应置于 Provider Config。`RetryId` 关联 `llm/retry` 与 `llm/retry-started`。                                                                                                                                                                                                                                              |
| `TokenMeter`                                                     | `measure(session,requestHeader?)` 给冻结的 Session 压力快照；`estimateMessage(message)` 给固定启发式价。                                                                                                                                                                                                                                       |
| `TokenMeasurement`                                               | `logRevision`、`baseline`、`surfaceDeltaTokens`、`totalTokens`、`surfaceTokens`、`nodes`；读数有日志版本，不是精确账单。                                                                                                                                                                                                                       |

## 来源与验证

事实来自目标 `packages/llm/{llm-deepseek,llm-deepseek-api-key,llm-deepseek-account,llm-pi-ai,llm-retry,token-meter,plugin-package-inventory-deepseek}/src` 的根导出、实现和相关测试。逐包映射与独立验证见 `evidence/runtime/llm-builtins-retry-meter-review.md`。通用新增 Provider 的完整注册/stream 契约仍由 [LLM Provider 适配器](api-llm-providers.md) 负责。
