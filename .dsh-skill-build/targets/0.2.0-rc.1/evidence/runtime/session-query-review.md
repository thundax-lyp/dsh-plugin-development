## Public/API owners and behavior

- `packages/session-query/session-query/package.json`, `src/index.ts`, `src/types.ts`, `src/config.ts`, `src/observation.ts`: root export has abstract `SessionQueryEngine`, filters/requests/records/observation lease, error taxonomy. `ctx.sessionQuery` exists only when concrete backend is mounted. Exact read/filter/trace methods are concrete; `searchSessions`/`searchEvents` abstract. `observeSession` returns disposable live/prepared cut. It uses `ctx.sessions`, optional `sessionPersistence`, and optional projection registry/cache. Read service has no caller authorization; direct use must remain trusted or be wrapped with caller checks.
- `packages/session-query/session-query-sqlite/package.json`, `src/index.ts`, `src/query.ts`, `src/schema.ts`: concrete service with dedicated derived SQLite FTS5 index. Config `path`, `openAt`, journal/page/snippet/read/cache options. Search normalizes literal phrase, reconciles live/persisted sources, returns generation-bound cursor and fails stale rather than shifting a page. `openAt: never` leaves exact operations available while search fails. `close()` drains accepted queue and closes handle. Unit and Loader tests in `tests/`; inspected source/test inventory, not run.
- `packages/session-query/tool-session-query/src/index.ts`, `src/workspace-access.ts`, `src/operations.ts`, `src/service-boundary.ts`: optional model-facing five-tool plugin. It requires `tools`, `systemPrompt`, `sessionQuery`, `sessionProjections`; derives caller Agent and exact-cwd authorization, then sanitizes service failures. Cross-session service itself does not provide this authority. Model tools use cursor-free text and can produce large results; generic spill policy is separate.
- `packages/session/session-projection/src/index.ts`: public `ctx.sessionProjections` registry with `ProjectionDefinition`, state map/client view declaration merges, effect-owned register and listener, synchronous pure fold, `stateVersion` checkpoints, live snapshot and cold restore. This is the domain projection authoring contract; it deserves a separate API owner if included, rather than being swallowed by query docs.
- `packages/session/session-projection-cache/src/index.ts`: public Host service `ctx.sessionProjectionCache`, config requires positive `writeEveryEvents`/`writeIntervalMs`; `storageDomain` backend retains derived state checkpoints keyed to Session lifecycle, stateVersion and seq. Fail-soft writes, not source of truth. `packages/storage/storage-domain` and JSON backend are underlying storage providers, not interchangeable with Session persistence or FTS index. Need separate storage-domain API adjudication before claiming full plugin author coverage.
- `packages/bundle/base/cordis.patch.yml:140-187`: mounts SQLite service with `path: ':memory:'`, `openAt: never`, projection registry, storage stack, projection cache with 200 events/5000 ms. `packages/bundle/web-app/cordis.patch.yml:23-33` preserves search disabled. `@deepseek-ai/dsh-tool-session-query` is not in these default bundle rows and not a base/web-app dependency. `apps/cli/README.md` explains patch order and package commands.
