# Client store + staged file upload consumer review

Target `dsh-v0.2.0-rc.1`, commit `4878cdabd87d4041bdaff61d04c966883b9fd07a`. All new files are in the ignored target build tree; no shared ledger, formal Skill or target checkout source was changed.

## Code path checked

- `packages/client/store/src/index.ts` and `contract.ts`: `defineStore` creates a handle; renderer owns production instances and synthesizes `PropsStore` hooks. `createSnapshotStore` is bare state, default synchronous notification, optional raf batching and localStorage persistence. `clearPersisted` is explicit and not part of ordinary scope disposal. The example is `skill-source/how-to/add-stateful-client-slot.md` and `evidence/tests/client-store-upload-consumer/src/stateful-slot.tsx`.
- `packages/client/ui-renderer/src/client/registry.ts`: the registered `store` seat is acquired with the slot entry/scope and released with registration lifecycle. The Client plugin `apply` creates the handle, not module-level singleton state.
- `packages/client/file-upload/src/client/contract.ts`, `runtime.ts`, `index.ts`, `types.ts`: `ctx.fileUpload.upload` accepts Blob/stream/bytes, returns `RemoteResult<FileUploadValue>`, passes cancellation, and chooses Worker HTTP for Blob/stream versus Remote base64 for exact bytes. `FileUploadValue` has `receiptId` and durable file ref.
- `packages/client/file-upload/src/index.ts`: Host service stages receipt under Agent/Session ownership and registers the file route; `registerAgentResolver` is an exclusive Host resolver, not a multiple-provider extension registry.
- `packages/api/session-controller/src/client/contract/session.ts` and `sessions/session.ts`: `SessionFace.prompt` accepts file receipt content; subagent file parts are explicitly rejected. `packages/client/ui-conversation/src/client/service.ts` uses `fileUpload.upload`, carries ready receipt into `prompt`, and handles draft cancellation/retirement. The independent example is `skill-source/how-to/upload-and-submit-file.md` and `evidence/tests/client-store-upload-consumer/src/upload-and-submit.tsx`.

Initial Node smoke failed with `ERR_MODULE_NOT_FOUND: Cannot find package 'zustand'` from the published `dsh-client-store/lib/index.js`. The exact target `packages/client/store/package.json` lists `zustand` and `immer` only in `devDependencies`, while published `lib/index.js` imports them at runtime. The fixture now explicitly installs versions compatible with the target (`zustand ~4.4.7`, `immer ^10.1.1`). This is a package-consumer boundary worth retaining in the reference; it does not invalidate the Client type compile.

The upload HOW-TO distinguishes an uploaded staged receipt from accepted Session content, aborts owner operations on component teardown, and checks both upload and prompt `RemoteResult`. An abort after Host acceptance does not roll back the Session event. The direct Host protocol fixture now proves that a 46-byte inert fixture file passed the upload route and appeared as a durable file ref in the same Session record as a unique prompt marker. This does not prove the browser Worker, progress callbacks, UI cancellation or reconnect paths.

The separate `browser-upload-half/` fixture was also built and loaded in an isolated `upload-smoke` Web Profile on local port `43912`. Chrome visibly showed `Choose probe file` in the Session header. The agent-created `upload-probe.txt` contains only an inert test sentence, but Chrome's file chooser refused `setFiles` before transfer because the ChatGPT browser extension lacks local file URL access. The browser's documented recovery is: To enable file upload, open chrome://extensions, click Details under the ChatGPT browser extension, and enable "Allow access to file URLs." See [here](https://developers.openai.com/codex/app/chrome-extension#upload-files) for details. The plugin was removed from the isolated Profile, test tab closed, and server stopped. This Chrome test does **not** establish `Staged`, `Submitted`, byte persistence, or cancellation behavior.

## Direct Host protocol observation

The same isolated `upload-smoke` Profile was restarted without the UI probe on local port `43913`. `direct-remote.mjs` exchanged that launch's ephemeral token for the signed browser cookie without storing either secret, called `session/list` for the real catalog identity (`session-` prefix matters), and sent the fixture bytes to the authenticated streaming route. The response was `ok: true` with a fresh receipt and `FileAttachmentRef` (`name: upload-probe.txt`, `bytes: 46`, content id `sha256:e02604650512f8194a55ed362db4ddb7548eb62cad62c7302d0b0d03133b7133`). A Typert Connection envelope then called `session/prompt` with that receipt and unique request marker; it returned `accepted: true`. `session/list` supplied `projections.asOfSeq`; `session/page` at that cursor returned a record containing both the unique marker and the same file content id. The final script exited 0, and the local server was stopped.

Before using the HTTP route, a direct `fileUploads/upload` Remote call against the cold Session returned `session/not-found`: this Remote method resolves a live Agent scope, whereas `uploadFileBinary` uses the Session controller's registered Agent resolver for a cold ordinary Session. Earlier exploratory attempts also used a directory UUID without the catalog `session-` prefix and failed `session/not-found`; `session/list` clarified the canonical identity. An initial `session/page` request with `Number.MAX_SAFE_INTEGER` failed because `throughSeq` cannot exceed the current cursor; the final fixture derives it from `projections.asOfSeq`. These failures did not pass the validation gate and are not counted as successful uploads.

## Isolated Web Profile observation

The `browser-half/` fixture uses a fresh `DSH_HOME`, `stateful-smoke` Profile copied from the published Web default, and local port `43911`. Its Host entry is an empty Loader row; the Client factory requires the published baseline `@deepseek-ai/dsh-client-store`, creates `defineStore` in `apply`, and registers a Session-header list entry with `store`. `npm run build`, Profile creation with `--from-default-profile web --dump-config`, and `dsh plugin --profile stateful-smoke add <fixture>` exited 0. Chrome showed the installed button in a newly created Session. The first message's model turn failed `MISSING_CREDENTIAL` because the isolated Profile has no model key; this did not prevent UI observation.

Chrome accessibility observations: initial Session `Count 0`; after click `Count 1`; new-session hero no `Count` button; returning to original Session `Count 0`. `dsh plugin --profile stateful-smoke remove dsh-stateful-slot-probe` exited 0 while the server ran; Chrome then removed the button without a reload, and a later config dump had no probe row. The agent-created tab was closed and server stopped. This verifies an ephemeral store seat's visible update and disposal in one local Web Profile. It does not test `persist`, two simultaneous Session views, production TSX bundling or a Host upload.
