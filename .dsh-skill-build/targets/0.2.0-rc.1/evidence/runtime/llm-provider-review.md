# dsh-v0.2.0-rc.1 LLM Provider and model routing review

Target commit: `4878cdabd87d4041bdaff61d04c966883b9fd07a`. Only exact checkout source and installed exact npm declarations were used; no formal Skill input.

## Public entry and runtime evidence

- `packages/llm/llm/package.json` exports root, `./types`, `./brand`, `./message`, `./assistant-stream`, `./invariant`, generated `./typert` and `./remote`; `src/{index,types,attribution,adapter-failure}.ts` owns adapter registry, request/chunk vocabulary and errors. `packages/bundle/base/cordis.patch.yml` mounts LLM service and `agent-default-model`, pi-ai adapter dormant until configured, credential Provider and adapter-related services. The base patch also mounts DeepSeek API-key/account adapters at later lines; those implementations were not fully reviewed here.
- `LlmAdapter.stream` is required; `registerAdapter` validates routes atomically and returns disposer/replace. `listModels` defaults empty and is advisory for core, but Session Controller GUI requires exact catalog membership. `resolveModel` is exact-route metadata, checked and detached by `LlmRuntime`. `prepareCall` binds one adapter generation and is one-shot. `registerConfigurableProviders` is a separate directory for dormant settings routes; it does not activate routing by itself. `llm/stream` waterfall can short-circuit terminal dispatch.
- `packages/core/agent/src/model-selection.ts` exports `ModelSelection`, `ModelSelectionRef`, `installModelSelection`; three scoped listeners snapshot route/effort and insert a durable switch notice. `packages/core/agent-default-model/src/index.ts` supplies volatile default selection and optional queued config-editor saves. `packages/api/session-controller/src/{commands,agent,catalog,model-selection-projection,types}.ts` owns GUI selection validation, Session event append, request-header fold, and Remote views. Web app patch mounts Session Controller; model-selection Client is a separate Web concern.
- `packages/llm/llm-pi-ai/src/{index,config}.ts` shows built-in multi-route registration and per-request `ctx.credentials.resolve`, with dynamic settings. A named `apiKeyEnv` that misses throws `MISSING_CREDENTIAL` instead of falling into unrelated ambient discovery; omission alone allows provider-native discovery. This is implementation evidence, not a requirement to use pi-ai in every custom adapter. `docs/cookbook/adding-an-llm-adapter.md` gives protocol checklist; source adjudicates details. No `@deprecated` marker was found for the reviewed root types/members in these source files.

## Isolated validation

- `evidence/tests/llm-adapter-consumer` is a newly created independent package pinned to `@deepseek-ai/dsh-llm@0.2.0-rc.1` and `@deepseek-ai/cordis@4.0.4`. `npm install --ignore-scripts --no-audit --no-fund` passed. `npm run build` passed with TypeScript 6.0.3. `npm pack --dry-run --json` listed patch, `lib/index.js`, `lib/index.d.ts`, manifest.
- `node smoke.mjs` passed against installed packages: a Cordis Context mounted `LlmRuntime` and plugin fiber; `listProviders()`/`listModels()` showed the route/model; an empty-message `ctx.llm.stream()` emitted `block-start,text-delta,block-end,usage,finish`; a user-message call normalized the fixture's `UNSUPPORTED_OPTION` exception into an error finish; disposing plugin fiber made provider list empty. The fixture explicitly refuses inputs and controls it does not implement, so it is an in-process Core behavior test, not an Agent-ready provider, Profile/Web or real network provider test.
- No Host Profile installation, Agent turn, Web model selector, generated Remote compile, provider credential exchange, HTTP attribution, cancellation under I/O, or retry/recovery was run.
