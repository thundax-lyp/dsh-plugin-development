# API controller Client/Remote disposition

Target: `dsh-v0.2.0-rc.1`, commit `4878cdabd87d4041bdaff61d04c966883b9fd07a`. This is a source-led disposition of whether an external package can contribute **to** the shipped Client controller/Remote registries. Public consumer methods are distinct from provider registration.

| Package | Exact public Client/Remote source | Disposition for plugin authors |
| --- | --- | --- |
| `@deepseek-ai/dsh-api-session-controller` | `src/client/index.ts` exports Session object, `ISessions`, stream helpers and `SessionReferenceSourceMap`; `apply` constructs one `ClientSessions`, binds forwarded events/control stream, and registers its own Typert `agent` context. `src/client/contract/sessions.ts` has retain/using/create/fork/search/scope methods. Package exports `./client`, `./types`, `./remote`. | A third-party Client may **consume** `ctx.sessions` and declaration-merge `SessionReferenceSourceMap` for its retain source label. The latter is type vocabulary, not a runtime registration callback. No API here registers a new Session controller or Remote method into the shipped namespace. New business Remote goes through its own Remote contribution and Client mounting path. |
| `@deepseek-ai/dsh-api-workspace-controller` | `src/client/index.ts` exports `IWorkspaces`, `WorkspaceController`, `createWorkspaceStateStream`, and model types. `apply` constructs one controller and one reconnecting follow stream over `remote.workspace`; `src/client/service.ts` exposes create/initializeDefault/rename/delete/order/archive/pin etc. Package exports `./client`, `./types`, `./remote`. | Public Client **consumer** service and reusable stream constructor, but no additive workspace provider registry or method registration. An external UI may call `ctx.workspaces`; it should not replace the owning Client service to extend Workspace semantics. |
| `@deepseek-ai/dsh-api-job-controller` | `src/client/index.ts` exports `IJobs` and job views; `apply` constructs one `ClientJobs` over `remote.job`. `src/client/service.ts` exposes `watchRows`, `observe`, `kill`, snapshots; package exports `./client`, `./types`, `./remote`. | Public observation/kill **consumer** face. Job producer registration is elsewhere (`dsh-jobs`/local Host registry), not a Client controller provider seam. No register/add method on `IJobs`. |
| `@deepseek-ai/dsh-api-terminal-controller` | `src/client/index.ts` exports `ClientTerminals` and `ctx.webTerminals`, installs one service over `remote.terminal`; `view`, `launchShells`, `selectShell`, `close` manage terminal occurrences. Package exports `./client`, `./types`, `./remote`. | Client UI may consume terminal view management. No third-party terminal controller registrar; its `view` creates/returns occurrence state and is not a provider registration point. |
| `@deepseek-ai/dsh-api-settings-controller` | `package.json` exports root, `./types`, `./typert`, `./remote`, but no `./client`; `src/index.ts` owns the Host settings Remote. | No dedicated Client controller face to register a settings namespace. The shipped `settings` Remote is a generated Host capability. Plugin-owned settings UI or new Remote methods require their own settings/Remote extension path; do not infer extension from the name of this package. |
| `@deepseek-ai/dsh-api-remotes` | `src/client/index.ts` imports a fixed list of generated Remote contributions and `apply` mounts them sequentially with `ctx.remote.$mount`, unwinding on failure. `src/index.ts` registers the application's fixed forwarded-event allowlist on Host. | This package is an **assembly**, not a mutable third-party namespace catalog. An external Remote contribution can use the Gateway/Remote creation and mount mechanism in its own package, but is not inserted into this fixed list or forwarded-event allowlist automatically. `ctx.remote.$on` is limited to the selected event face. |

This audit inspected source and public package exports; it did not build an independent consumer for these controller faces or exercise the generated Remote gateway at runtime. Route consumer tasks to the relevant Session/Workspace/Jobs/Terminal reference if needed, and new Remote provision to the separate Remote HOW-TO. Do not count the names of `./remote` export subpaths as evidence of a third-party registry inside a controller.
