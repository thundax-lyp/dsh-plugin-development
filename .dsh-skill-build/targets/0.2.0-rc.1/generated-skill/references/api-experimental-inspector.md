# 实验 Inspector 诊断端点

## 可用任务与 Profile

目标 `dsh-v0.2.0-rc.1` 的 `@deepseek-ai/dsh-experimental-inspector` 是已发布的可选 Host 插件。作者可把它显式加入**有 `webServer` service 的诊断 Profile**，得到独立 loopback HTTP/CDP Worker 端点和注入到 Web index 的 Client bootstrap。完整安装见 [启用 Inspector](how-to-enable-experimental-inspector.md)。`packages/experimental/inspector/cordis.patch.yml` 是已发布的 bundle patch；`cordis.source.patch.yml` 将相对 `.ts` 入口交给仓库 demo/tsx，不能作打包插件的生产路径。

## 对象类型与成员

| 入口                                            | 成员与边界                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 根插件                                          | `name = 'experimental-inspector'`、`inject = ['webServer']`、`Config`、`apply(ctx, config)`。Host 装载时启动 Worker，发布 `ctx.inspector`，响应 `webserver/index-inject` 注入 `__DSH_INSPECTOR__`；fiber 卸载时撤销服务/监听并关闭 Worker。                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `Config` / `InspectorOptions` / `InspectorSpec` | `host` 只能是 `127.0.0.1`；`port` 从指定值寻找空闲端口，`0` 请求系统分配；`clientOrigins` 是额外允许的浏览器 Origin；`captureFetch` 默认 `true`。边界字段为 `maxRequestBodyBytes`、`maxResponseBodyBytes`、`maxBodyChunkBytes`、`maxJournalBytes`、`maxRetainedRequests`、`maxSourceFrameBytes`、`maxSourceRecordsPerFrame`、`maxQueuedRecords`、`maxQueuedBytes`、`startupTimeoutMs`、`stopTimeoutMs`、`clientReconnectBaseMs`、`clientReconnectMaxMs`、`clientRuntimeTimeoutMs`、`queryTimeoutMs`、`maxClientRuntimeObjects`、`maxClientRuntimeProperties`、`maxClientSourceBytes`、`maxCordisNodes`、`maxDisconnectedCordisTrees`。根插件的 schema 默认端口 `9230`，直接 `startInspector()` 的库默认 `0`。 |
| `resolveInspectorOptions`                       | 将 `InspectorOptions` 解析为 `InspectorSpec`，检查端口、frame/编码块容量、重连上下界和 canonical `clientOrigins`；它只校验配置，不启动 Worker。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `startInspector` / `InspectorHandle`            | 直接库入口可返回 `{endpoint,source,close()}`；`endpoint` 含 `httpUrl`、`webSocketDebuggerUrl`、`devtoolsFrontendUrl`、Client ingest bootstrap。直接调用者必须拥有并 await `close()`；通常插件作者应使用 Cordis 根插件，让 fiber 拥有清理。                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `InspectorService`                              | `cordis` 给出诊断树读取面，`publish` 提交受限的诊断记录；这是 Inspector 自身的 Host service，不是任意 web route 注册表。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `InspectorClientBootstrap`、`./client`          | bootstrap 提供 `endpoint`、随机 `protocol`、`maxQueuedRecords`、`maxQueuedBytes`、`maxRecordsPerFrame`、`maxFrameBytes`、`reconnectBaseMs`、`reconnectMaxMs`、`queryTimeoutMs`、`maxRuntimeObjectsPerSession`、`maxRuntimePropertiesPerResult`、`maxClientSourceBytes`、`maxCordisNodes`；Client 模块是 Inspector 自身跨侧组成。                                                                                                                                                                                                                                                                                                                                                                              |

`InspectorEndpoint` 是 `startInspector` 的端点记录，包含 `httpUrl`、`webSocketDebuggerUrl`、`devtoolsFrontendUrl` 与 `client` bootstrap；URL 仅在对应 Worker 活着且本机可访问时有效。

## 访问控制、失败与停止

Worker 只监听 `127.0.0.1`。`/json`、`/json/list`、`/json/version` 列出 CDP 目标；`/devtools/page/<target>` 是 CDP WebSocket。**CDP 路径没有 Client ingest 的 protocol token 或 Origin 门禁**，因此该端点只适合受控本机诊断环境，不能代理到非可信网络。`/ingest` 要求随机 `Sec-WebSocket-Protocol` token；无 Origin 的非浏览器请求与 localhost/loopback Origin 可通过，其他 Origin 必须在 `clientOrigins` 精确列出。`clientOrigins` 不是对 CDP 路径的访问控制。

启动失败会终止 Worker/MessagePort，Host 插件注册中的部分 service/监听会回滚。`close()` 停止收录与 fetch observer、关 socket/CDP session 并等待 Worker；若停止异常须保留/报告错误，不能只因 fiber dispose 被调用就声称资源已释放。启用 `captureFetch` 会观察当前进程的 global fetch，诊断数据可能包含请求/响应正文，故仅在自有诊断 Profile 使用并设定字节上限。
