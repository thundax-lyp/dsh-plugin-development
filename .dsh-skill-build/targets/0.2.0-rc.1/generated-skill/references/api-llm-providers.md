# LLM Provider 适配器与注册

## 适用范围与入口

目标 `dsh-v0.2.0-rc.1` 的 Host 插件从 `@deepseek-ai/dsh-llm` 根入口导入 `LlmAdapter`、`LlmRuntime`、`LlmError`、`GenerateOptions`、`StreamChunk`、`BlockAssembler` 等；`./types` 是类型面，`./brand`、`./message`、`./assistant-stream` 各有专门的公开类型/工具，`./typert` 和 `./remote` 是生成的跨侧入口。base bundle 装载 `ctx.llm`；自定义 Profile 必须先装载它，适配器插件声明 `inject = ['llm']`。本文负责插件新增 provider route 的唯一契约；自有 DeepSeek Messages route 的最小包见[注册自有 Messages route](how-to-register-custom-deepseek-route.md)，用户如何选择模型见 [模型路由](api-llm-model-routing.md)。

## 契约与运行语义

继承 `LlmAdapter` 并实现 `stream(options: GenerateOptions): AsyncIterable<StreamChunk>`。调用 `ctx.llm.registerAdapter(providers: string[], adapter)` 绑定至少一个非空 provider route；重复、空名或 `providerInfo` 的 id 不匹配会同步失败，整组不部分注册。返回 `AdapterRegistrationHandle` 是函数 disposer，另有 `.replace(next: string[]): void` 原子换路由，替换为空数组合法；处置后 replace 抛 `REGISTRATION_DISPOSED`。注册与注销都会使 `listProviders()` 变化并发出 `llm/adapters-updated`，消费者重读目录。Host 调用 `ctx.llm.stream(options)`，`options.provider` 选择注册的适配器，`options.model` 原样交由适配器，核心不要求事先注册 model id。

`LlmAdapter.providerInfo(provider)` 默认返回 `{id: provider, name: provider}`；`providerRetryPolicy(provider)` 可给路由重试策略；`listModels(provider)` 默认空目录，需要 Web 模型选择的适配器要实现它；`resolveModel(provider, model, signal?)` 默认返回基本身份，异步解析器必须响应取消，可补充 context、reasoning、默认输出 cap、输入模态等精确模型元数据。`prepareCall` 可把动态配置的一代元数据与 stream 绑定，避免设置变化造成端点和能力错代；`ctx.llm.prepareCall` 返回一次性的 `PreparedLlmCall`，使用后再次 stream 或篡改 config 抛 `INVALID_PREPARED_CALL`。`registerConfigurableProviders(entries)` 是可配置 route 的目录，即使当前未装载 adapter 也可展示；其 `settingsNs`/`settingsPath` 指向设置位置，目录不是运行时注册，且也有 disposer 和原子 `.replace`。

目标 base bundle 另有 `@deepseek-ai/dsh-llm-pi-ai`，初始 `providers` 为空，未配置时不注册可运行 route。其 `Config.providers` 是 `Volatile<Record<string, PiAiProviderProfile>>`；字典键就是 route。已安装 pi-ai 目录中的 route 可继承端点、协议和模型列表；自行声明的 gateway 要给 `api`、`baseURL` 和非空 `models`。每个 profile 的 `apiKeyEnv?: string` 是凭证引用，插件每次请求通过 `ctx.credentials.resolve` 读取；引用存在却解析不到值时抛 `MISSING_CREDENTIAL`，不会退回可能属于另一租户的 pi-ai 环境发现。`apiKeyEnv` 完全省略时才由 pi-ai 自行发现认证。配置 route 集或注册时捕获的 retry 策略变化会原子替换注册，下一次请求读取新连接事实。完整 Profile 例子见[配置 pi-ai gateway 与包清单](how-to-configure-pi-ai-and-inventory.md)。这个现成 Provider 路径可用于配置供应商，而新协议或特定行为才需要自写 Adapter。

适配器发出的 chunk 要按首见顺序给 block 分配 index，`block-start` 与 `block-end` 配对；工具参数 delta 是原始 JSON 字符串；`usage` 在唯一终止 `finish` 前发出，之后无 chunk。传输或协议失败可抛 `LlmError`，或以 `finish.reason.kind: 'error'/'aborted'` 报告带 `LlmFailure` 的 in-band 失败。不能默默丢弃不支持的请求字段：抛 `UNSUPPORTED_OPTION`。网络请求要传递 `options.signal`，每次请求通过 `attributionHeaders()` 加公开、固定的 `User-Agent`；秘密不进入此 header。已发布 DeepSeek 与 pi-ai adapter 可作为不同传输实现的源码范例；其特有协议不提升为所有 adapter 的默认行为。

## 对象类型与成员

`AdapterRegistrationHandle` 和 `DirectoryRegistrationHandle` 均是带 `replace(next)` 的函数 disposer；分别拥有 adapter route 与可配置 provider 目录。`PreparedLlmCall` 暴露 `config`、`adapterDefaults`、`retryPolicy`、`context`、`inputModalities`、`systemPromptUpdate`、`toolUpdate` 和一次性 `stream`，不能跨配置代复用。`FinishReason.kind` 是终止原因判别；`LlmError.failure` 是规范化的 `LlmFailure`。`LlmRuntime` 暴露 `registerAdapter`、`registerConfigurableProviders`、`listProviders`、`listConfigurableProviders`、`listModels`、`resolveModelInfo`、`resolveCallConfig`、`prepareCall`、`stream`；直接适配器和目录各自拥有生命周期。

`@deepseek-ai/dsh-llm/invariant` 是可选诊断插件，不是普通 Provider 注册的前置；启用后，错误的 block index、delta 顺序或终止后继续输出会在流消费处被拒绝。

## 生命周期与状态

注册句柄归插件 fiber，卸载时释放 route 和目录条目；动态配置更新时可原子 replace。直接 `ctx.llm.stream()` 是一次 provider 请求，没有 Agent 级持久重试；Agent loop 的另一次重试是 Session 日志记录的独立请求。成功的 adapter-private `finish.replayState` 可随已组装 assistant 消息持久化，只有历史 route 与目标 route 当前属于同一 adapter 实例时才传回该实例；无可用状态时走 provider-neutral 内容。插件需验证自己保存的 replay 数据，不能把任意旧 provider 元数据当成当前请求状态。

## 失败、权限与边界

目录只是建议，GUI 等目录驱动入口可要求 catalog membership，核心路由仍可接收未列出的 model id。`resolveModelInfo` 校验并分离 adapter 返回值；无效目录、模型身份或推理选项会拒绝。`llm/stream` waterfall 可以在最终 adapter 查找前短路；不能以收到 stream handle 证明网络 I/O 已发生。Provider 凭证读取应经 [凭证 Provider](api-credentials.md) 每次请求重新解析；不要长时缓存，也不要在日志/Session/模型消息里保存值。HTTP adapter 自行负责超时、取消和 SDK 内部重试控制。

## 验证

源码：`packages/llm/llm/src/{index,types,attribution,adapter-failure}.ts`。注册/目录与调用边界见 `packages/llm/llm/tests/{topology,service}.spec.ts`；已发布 adapter 的请求、流和动态配置测试分别在 `packages/llm/llm-deepseek/tests`、`packages/llm/llm-pi-ai/tests`。隔离固定文本适配器已通过 Host 编译、pack dry-run 与进程内 Cordis 的注册、目录、空消息 chunk 顺序、拒绝未支持请求、卸载检查。它不能处理实际 Agent 消息；真实 Profile、Agent、凭证、网络和 Web 路由尚未运行。
