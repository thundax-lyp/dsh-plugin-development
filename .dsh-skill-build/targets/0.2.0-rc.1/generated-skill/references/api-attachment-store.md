# 附件存储与耐久引用

## 入口和职责

目标 `dsh-v0.2.0-rc.1` 的 Host 插件从 `@deepseek-ai/dsh-attachment` 根入口使用 `AttachmentStore`、入站校验函数、附件 ref 与错误类型；`@deepseek-ai/dsh-attachment-local` 提供可装载的本地实现 `LocalAttachmentStore`。Profile 必须恰好装载一个 `ctx.attachments` service，消费插件声明 `inject = ['attachments']`。完整消费路径见 [接收并读取附件](how-to-use-attachment-store.md)。

## 公开成员

| API                                                                           | 用途和边界                                                                                                                                                                                                                                                                                                         |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `AttachmentStore.imageLimits`、`validateImage`、`saveImage`、`readImage`      | 自定义 provider 必须实现的图像校验、持久写入、校验读取。ref 中 `attachmentId` 不得是路径或 bearer URL。                                                                                                                                                                                                            |
| `saveImages(inputs)`                                                          | 先校验整个有序批次，再逐个保存；校验失败不开始写。存储中途失败不返回部分 ref，已持久化对象可能暂时不可达。                                                                                                                                                                                                         |
| `admitPromptContent(parts)`                                                   | Host 收到 prompt 后提升上传图像为耐久 ref；文本和已解析文件 ref 原样传递；没有图像就不进行存储。                                                                                                                                                                                                                   |
| `admitEncodedFile(input)`、`admitEncodedImages`、`admitEncodedFile`           | 规范 base64 入站验证，提交耐久对象；前者是 service 方法，后两者是根入口函数。                                                                                                                                                                                                                                      |
| `saveFile`、`saveFileStream`、`readFileStream`                                | 原样文件存储与有界分块读取；抽象基类默认以 `ATTACHMENT_FILES_UNSUPPORTED` 拒绝，provider 要显式实现。流式 provider 必须背压，不能完整收集到内存。                                                                                                                                                                  |
| `readImageRequest(ref,target,signal?)`                                        | 按模型路由选择的尺寸/字节目标生成可复用 request variant；基类默认 `ATTACHMENT_PROJECTION_UNSUPPORTED`。                                                                                                                                                                                                            |
| `imageHostPath`、`fileHostPath`                                               | 仅 host-file-backed 后端可返回绝对路径；非本地实现默认 `undefined`。不能暴露为浏览器 URL。                                                                                                                                                                                                                         |
| `AttachmentError`、`isAttachmentError`、`isImageAdmissionError`               | 按稳定错误代码识别本能力失败，不按错误文字判定。                                                                                                                                                                                                                                                                   |
| `LocalAttachmentStore`                                                        | 本地实现公开 `root`、`normalizationPolicy`、`imageCompressionConcurrency`、`imageLimits`，并实现 `validateImage`、`saveImage`、`saveImages`、`readImage`、`readImageRequest`、`saveFile`、`saveFileStream`、`readFileStream`、`imageHostPath`、`fileHostPath`。`root` 是服务内部存储根，不能当作客户端可访问路径。 |
| `FileAttachmentRef`                                                           | `attachmentId`、`name`、`bytes` 是可序列化文件引用字段；内容校验仍在读取时进行。                                                                                                                                                                                                                                   |
| `ImageAttachmentRef`                                                          | `attachmentId`、`mediaType`、`bytes`、`width`、`height`、可选 `name` 与 `originalDimensions` 描述已规范化图像。                                                                                                                                                                                                    |
| `RequestImageAttachment`                                                      | `variantId`、`attachment`、`data`、`mediaType`、`bytes`、`width`、`height`、`depth`、`space`、`hasAlpha` 描述针对请求生成的版本；`data` 是字节，不应直接序列化为 Session 引用。                                                                                                                                    |
| `SaveImageAttachment`                                                         | `data: Uint8Array`、声明的 `mediaType`、可选显示 `name`；存储层必须核实字节与声明媒体类型一致。                                                                                                                                                                                                                    |
| `SaveFileAttachment` / `SaveFileStreamAttachment`                             | 前者 `data: Uint8Array`，后者 `data: AsyncIterable<Uint8Array>`、可选 `signal`；两者可选显示 `name`，不可将它解释成路径。流式 provider 必须背压。                                                                                                                                                                  |
| `ImageAttachmentLimits`                                                       | `maxImageBytes`、`maxImagesPerMessage`、`maxMessageImageBytes`、`maxImagePixels`、`maxImageDimension`、`mediaTypes`；由部署解析，用于入站图片校验，不是调用方绕过限额的参数。                                                                                                                                      |
| `ImageRequestTarget`                                                          | `width`、`height`、`maxBytes` 由精确模型路由选定；高于原图的尺寸不放大，超出字节目标时保留最小质量梯级。                                                                                                                                                                                                           |
| `PromptContentPart` / `AttachmentAdmissionPart` / `AdmittedPromptContentPart` | Browser prompt 是 text/image bytes；Host admission 可接受已解析 file ref，并把 image bytes 提升为耐久 `ImageAttachmentRef` 后再构造 Session 消息。                                                                                                                                                                 |

`ImageAttachmentRef` 记录 opaque id、已验证媒体类型、编码字节数、宽高、可选去路径化显示名及被缩小时的原始尺寸；`FileAttachmentRef` 保存 SHA-256 内容 id、清理后的显示名和精确字节数。两者是 Session 可序列化的耐久引用，不能替代原始字节的真实性验证。`RequestImageAttachment.variantId` 覆盖 ref、策略和固定编码参数；request variant 与储存的规范图像不同。

**精确 API 对象与成员**

`@deepseek-ai/dsh-attachment-local` 的 `Config` 供装载本地 backend：`dshHome?` 决定 `attachments/v1` 根目录；所有图像限额与 `normalizedImage*` 目标都是可选正整数，`imageCompressionConcurrency` 的有效范围为 1–8。未传值时使用包内默认值，不应把配置字段当作每次 `saveImage` 绕过部署限额的参数。`NormalizationPolicy` 是 service 上已解析的只读 `{ maxBytes, maxDimension, maxPixels }`；字节目标在最低质量仍超出时可能保留最低质量版本，不能把它解释为严格拒绝上限。图像变换在服务实例的并发限制内运行，调用失败不会返回持久 ref；已完成的写入由调用者再记录入所属 Session 事实。

| 对象/导出             | 纳入的成员                                                                                                                                                                                                                                                                                                  | 调用边界                                          |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| `Config`              | `Config.dshHome`, `Config.imageCompressionConcurrency`, `Config.maxImageBytes`, `Config.maxImageDimension`, `Config.maxImagePixels`, `Config.maxImagesPerMessage`, `Config.maxMessageImageBytes`, `Config.normalizedImageMaxBytes`, `Config.normalizedImageMaxDimension`, `Config.normalizedImageMaxPixels` | 本地附件 Service 装载参数；未设置时采用包默认值。 |
| `NormalizationPolicy` | `NormalizationPolicy.maxBytes`, `NormalizationPolicy.maxDimension`, `NormalizationPolicy.maxPixels`                                                                                                                                                                                                         | 本地 Service 解析后的规范化目标。                 |

## 生命周期和失败

插件调用 `ctx.attachments` 不拥有 service 根目录；`LocalAttachmentStore` 的 root 位于指定 `dshHome` 下 `attachments/v1`。调用者应先完成写入并得到 ref，再追加所属 Session 消息或业务事件；调用失败不能产生指向未写入对象的事件。读取需要验证 ref 和字节一致性并传播 signal。插件卸载不会删除耐久内容，保留/清理由部署存储政策负责。外部导入路径应先做自身权限和大小限制；本地 store 的配置限额只适用于其定义的入口，文件路径/引用不能当授权凭据。

自定义后端虽可继承 `AttachmentStore`，必须提供与本地后端等价的字节校验、不可变内容寻址、规范图像、文件流、request projection 和恢复能力，不能把测试用 fake 当生产后端。对于普通插件，消费部署已装载的 service 比自行注册第二个 attachment service 更合适。
